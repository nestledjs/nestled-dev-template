## A verifier false positive — caught and corrected

The round-4 verifier returned `NEEDS_WORK`, claiming a `.env`-supplied `WEB_URL` is invisible to the
module-scope capture because "plain node does not pre-load `.env`".

**That was wrong, and I disproved it before acting.** `apps/api/src/main.ts:1` is
`import 'dotenv/config'`, which precedes the config-barrel import at `main.ts:5`. Tested directly
with `WEB_URL` supplied *only* via `.env` and main.ts's real import order:

```
.env WEB_URL seen at module scope? YES
cors.origin = ["https://app.example.com"]  ->  ALLOWED
```

Rather than override the gate unilaterally, I re-ran the verifier pointed at the evidence it had
skipped (main.ts's first lines), instructing it to determine the ordering itself and report whatever
it found. It then confirmed the ordering, withdrew the claim, and its only remaining item was a
**factually false sentence in a code comment** — explicitly non-behavioral.

**This is the second time a verifier round produced a wrong blocking claim** (round 2's Copilot
`docker compose down` item was the first). Both were caught by reproducing the claim instead of
trusting it. Worth keeping: the verifier is a strong gate but not an oracle — every blocking finding
this cycle was independently reproduced before it was acted on, and two of them evaporated.

## Four-round retrospective

Every round found a strictly smaller defect, all in one small CORS function:

1. Origin followed `HOST` outright (`http://0.0.0.0:4200`).
2. Still followed it for every non-wildcard `HOST` (`http://127.0.0.1:4200`).
3. A supplied `WEB_URL` was used verbatim — a trailing slash blocked all CORS.
4. A false comment about module ordering (non-behavioral).

The convergence rule set in pass 2 was never tripped: it targets *ping-pong on the same unresolved
point*, and each round genuinely closed its predecessor. Pass 3 pre-committed to escalating if round
4 found another new **defect** in `webOrigin()` — round 4's finding was a false positive plus a
comment, so the code had in fact converged and escalation would have stranded a finished change.

The recurring theme is worth carrying forward: this function's behavior depends on **module
evaluation order**, which no unit test calling `configuration()` directly can observe. Three of the
four defects were invisible to the original spec for exactly that reason. The spec now exercises the
real validate → assign → `configuration()` path.
